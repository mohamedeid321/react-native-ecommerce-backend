# Lotta backend engineering instructions
Work on development branches; never deploy or merge without review. Preserve existing mobile API contracts during migration. Node ESM, Express, Mongoose, Upstash Redis, Cloudinary. Never commit secrets or use production data for tests.
Web auth: server-set HttpOnly Secure production host-only cookies for access and refresh; restrict refresh path to auth endpoints. Access 15m, refresh 7d, hashed refresh credentials in Redis, atomic rotation and reuse detection, per-device revocation. Explicit CORS allowlist, CSRF protection for cookie-authenticated mutations, distributed rate limits, strict validation, safe logging. Mobile uses bearer access and secure storage for refresh, with explicit migration plan. Google OIDC verified server-side; do not auto-link unverified identities. Register name/email/phone/password; login email or normalized phone. Google users complete missing profile data. Admin MFA before production.
Guest cart local product IDs and quantities only; authenticated merge validates server-side and is idempotent. Checkout requires account. Customer/admin/delivery authorization enforced server-side.
Use Cairo calendar dates, order cutoff configurable (initial proposal 22:00), scheduled delivery dates, historical snapshots, atomic checkout and cancellation, idempotency. Delivery reports require admin approval before customer delivered status. Purchases: aggregate scheduled noncancelled orders, record estimated and actual quantities/costs, compare variances. Financial reports distinguish booked sales, delivered revenue, cash collection, COGS and expenses. Preserve legacy data and document migrations.
Add tests for success, failure, concurrency and authorization; run lint/tests and integration tests against isolated databases before claiming completion. Document API contracts and environment variables. Do not expose secrets, internal errors, purchase costs or other users' records to customers.
